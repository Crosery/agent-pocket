# 0003 数值评审

评审对象：`docs/design/0003-story-and-progression.md`（#41）。角色：数值策划。只评数字，不改任何内容文件。
方法：用仓库真实引擎和真实 JSON 跑模拟，脚本全在 `/tmp/ap-review/`（不在仓库），命令见第 6 节。
记号：[verified] 已用代码或模拟复现；[assumed] 我的假设，写明了输入；[unverified] 没法在不改引擎的情况下验证。

## 1 结论先行

1. **0003 的等级检查点和"第 45–53 分钟进 Boss"在 0.18 遇敌率下不成立。** 只算设计里的脚本经验（零、属性课、两名路线一训练家、陪练、走廊训练家——走廊等级 0003 没写，我按 3×Lv7 + 2×Lv6 估），到第 45 分钟首发是 Haiku Lv8 / o1、V3 Lv8（设计写 Lv10），第 15–45 分钟每个检查点都低 1–3 级。补齐要 10–18 场草原野战，纯刷约 8–17 分钟。**内容本身只有约 24 分钟的量（对白 + 走路 + 战斗），45 分钟要靠刷凑。我建议"快速"定为第 22–25 分钟进 Boss（新手中位数），熟练 ≤ 15 分钟。**
2. **体验版数值照 §3.3.2 写，胜率目标全部落空。** 设计队伍 Lv10/7/6：朴素 0%，引导 o1 57% / Haiku 20% / V3 0%，o1 胜局只有 5 回合（目标 10–16）。根因是 V4 的先手克制 STAB 单发 31–36 点，Lv10 Haiku 只有 33 血。给出一组可落 JSON 的数值（atk/spa ×0.3、hp ×2.5），引导 ≥ 85–100%，并说明"朴素 35–60%"这个目标要改定义。
3. **Boss 卡追赶的核心前提错了。** §5.2 的表假定"每场的敌人和队伍同级"，路线一的敌人是 Lv3–6，经验只有同级（队伍 Lv10）的 1/5–1/3。按路线一余下训练家 + 5 场野战 + 开源林镇馆内全部训练家算，Lv1→队伍 Lv10 要 12 个击杀（上场）/ 19 个（替补），不是 3 / 7；"到开源林镇约 Lv12"实际是 Lv9（上场）/ Lv7（替补）。同时，上限取"下一馆王牌 +2"会让一张卡单挑 8 个馆里的 4 个必胜，直接违反 §5.5 自己写的"≤ 50%"。
4. **随机属性的两处硬伤：** 性格用 `floor` 取整，Lv1–10 时 +10% 的加成是 +0~+1，−10% 却是 −1~−2，Boss 卡 Lv1 时性格是纯负收益；LoRA 补丁定价太便宜，让 SS 稀有度归零（满血档卡 + 4 次补丁 ≈ 30 分钟内 SS 过半）。
5. **经济账基本闭合**（兑换价格都满足"所得 ≤ 所交"），没有套利路径；但 `persona-card` 15000 对 16000 只剩 6% 余量，钱缺少与 Boss 收入匹配的消耗。

## 2 问题清单

### 阻断

#### B1 第一小时时间账：等级检查点和进战时间都不成立

**现象：** §2.2 的"等级检查点"列（Lv7→8→9→10）和 §3.3.2 的开局队伍（Lv10 + Lv7 + Lv6）假定首发搭档在第 45 分钟前升到 Lv10。

**证据（算法：`expYield = floor(baseExp × 敌方等级 / 7 × 1.25训练家)`，`src/shared/creature.ts:202`、`content/config.json:17`；升级曲线 `floor(mul × L³)`，mul 慢 1.25 / 中 1.0，`creature.ts:43`、`config.json:22`；全部 [verified]）：**

| 来源（按设计时间） | 经验 | Haiku（中速，Lv5=125） | o1 / V3（慢速，Lv5=156） |
|---|---|---|---|
| 零热身 Lv3（11:00） | +37 | 162 = Lv5 | 193 = Lv5 |
| 属性课 3×Lv2（15:00） | +68 | 230 = **Lv6**（设计 Lv7） | 261 = **Lv5**（设计 Lv7） |
| 路线一 `r1-xin` Lv3 + `r1-jie` Lv4/3（30:00） | +30 +67 | 327 = **Lv6**（设计 Lv8） | 358 = **Lv6**（设计 Lv8） |
| 陪练 V2 Lv7，expMul 1（41:00） | +62 | 389 = **Lv7**（设计 Lv9） | 420 = **Lv6**（设计 Lv9） |
| 走廊两名训练家（45:00，等级 0003 没写，我假设 3×Lv7 + 2×Lv6 的 N）[assumed] | +335 | 724 = **Lv8**（设计 Lv10） | 755 = **Lv8**（设计 Lv10） |
| 离 Lv10 还差 | | 276 经验 | 495 经验 |

- 差额折成野战：草原野生平均 27.4 经验（Lv2–5，`content/world/regions.json` meadow + 种族 baseExp 均值），要 **10 场 / 18 场**；换成 `wild-meadow-2/3`（Lv3–9，N 级，均值约 47 经验）也要 6 / 11 场。
- 原点草原每格踩草遇敌概率 0.1 × 0.18 = 1.8%（`content/game.json:61`、`world/regions.json`），约每 56 个草格一战，走过去 17 秒 + 8 格宽限 2.2 秒 + 战斗 30–45 秒（[assumed]，按每回合约 7 秒、野战 4–5 回合）≈ 每分钟 0.9–1.2 战，**纯刷草只有 26–33 经验/分钟**。差额 = Haiku 约 8–9 分钟纯刷，o1/V3 约 15–17 分钟。
- 顺路碰到多少：原点到开源林镇的最短路线约 340 格，其中高草只有 66 格（最少草的路线只有 2 格）。`1−(1−0.018)^66` = 70% 至少一战，期望 1.2 战 ≈ 40 经验。所以**不刷就几乎没有野战经验**。（算法：A* 在 `buildWorld()` 的 `collisionField` 上跑，脚本 `/tmp/world3.ts`。）
- 补充：可见的游荡野生（`roaming`，上限 10 × 密度 0.6 = 6 只，`config.json` encounters.roamingMax、`src/client/world/roaming.ts:100-103`）碰到就开战，**不受 `grassRateMultiplier` 影响**。这是玩家自己选择的野战来源，大约每分钟 1–1.5 战 [assumed]。0.18 只砍掉了"被动遇敌"，要让新玩家知道可以主动碰，需要一次性引导。
- **内容真实时长约 24 分钟**：附录 A 对白 3183 字 / 45 字每秒（`content/ui.json:14`）≈ 71 秒，加约 140 次按键 ≈ 4 分钟；走路 ≈ 3 分钟；战斗（零 0.75、属性课 1、小新 0.8、阿杰 1.5、文心一言 2.2、陪练 1、走廊 1.5）≈ 9 分钟；商店 + 补给站 2 分钟；提示卡和菜单 3 分钟；Boss 首战 3 分钟 [assumed，战斗时长是估计]。**§2.2 的 45–53 分钟里约 20 分钟没有任何内容去填，只能是刷。**

**改法：**

1. 进 Boss 的目标：**新手中位数第 22–25 分钟，p90 ≤ 28，熟练 ≤ 15**；签约在第 28–30 分钟。依据：①所有者原话是"快速"；②上面的内容量；③到第 22 分钟，脚本经验已经够首发 Lv8–9（见下）。

   - 陪练的 `expMul` 设为 4（V2 Lv7 原始 62 → 248）。陪练输不了，正好当"训练语料大礼包"。
   - 走廊只留 1 名训练家（`ds-relay`，3×Lv6，183 经验），`ds-scalper` 改成可选。
   - 文心一言放在原点草原或 `wild-meadow-3`（见 I5），顺路 2–3 场野战，用一次性引导"碰一下画面里的智灵就能开战"。
   - 合计脚本经验 37+68+30+67+54+248+183 = **687**：Haiku 812 = Lv9，o1/V3 843 = Lv8；文心一言约 Lv6，第三只 N 约 Lv5。**把 §3.3.2 的参考队伍从 Lv10/7/6 改为 Lv8/6/5**（我下面的模拟也用 Lv8/6/5）。
3. `tutorial.json` 的"上岗清单"三项（文心一言、商店、补给站）里只留文心一言必做，商店和补给站改成顺路可选，由 NPC 直接给 2 张券和 5 瓶药，省 2 分钟。
4. 重排 §2.2 的时间列（新手视角）：

| 00–03 | 序幕、妈妈、选搭档（镇民闲聊收成可选） | 5 |

#### B2 体验版（`tiers.story`）：胜率目标全部落空

**现象：** §3.3.2 的目标是引导策略 ≥ 90%、朴素 35–60%、胜局 10–16 回合。

**证据：** 把 0003 的 `tiers.story` 原样翻译成 `BossDef`（level 12、statMul hp 1.5 / atk 1.0 / spa 1.0、招式权重、peak 0.15 / 1.0、valley 3.0 / 0.5、`residualMul` 0.4 用降低 leech 吸取量近似、enrage 18），队伍 = 首发 + 文心一言 + 随机一只 N（6 种轮换），150–300 个种子，背包 5 药 + 2 券。

策略定义（脚本 `/tmp/ap-review/story_boss.ts`）：
- **朴素**：每回合打预估伤害最高的招式，不用道具、不主动换人。（就是 0003 写的"只打最高伤害"。）
- **平衡 pilot**：`tools/balance/pilot.ts`，会补强、会换人、不用道具。
- **引导**：pilot + 血量低于 40% 喝药、高峰开头递半价券、高峰期用寄生或强化而不是白打、谷时输出。

| 队伍（首发/文心/N） | 配置 | o1 朴素/pilot/引导 | Haiku | V3（认亲按全程近似） |
|---|---|---|---|---|
| Lv10/7/6 | **0003 原值** | 0 / 0 / **57** | 0 / 4 / **20** | 0 / 5 / **0** |
| Lv8/6/5 | **0003 原值** | 0 / 0 / 16 | 0 / 0 / 7 | 0 / 0 / 0 |
| Lv10/7/6 | **建议值** | 27 / 79 / **100**（5 回合） | 1 / 88 / **98**（11） | 21 / 100 / **100**（15） |
| Lv8/6/5 | **建议值** | 1 / 43 / **100**（8） | 0 / 67 / **85**（12） | 9 / 100 / **100**（16） |
| Lv8/6/5 | 建议值 + 减负 | 73 / 91 / 100（5） | 2 / 91 / 100（7） | 82 / 100 / 100（10） |

原因（逐条 [verified]）：
1. **V4 打得太重。** Lv12 V4 atk 32（IV31，`calcStats`）；招式 70 威力、STAB、对 Haiku（代码）开源 ×2：手算 `floor(floor(6×70×32/16)/80)+2 = 12`，×1.5 ×2 = 36，随机 0.85–1.0 后 31–36（模拟日志里同样是"效果绝佳"后两发倒下）；Haiku Lv10 血量只有 33。第一发克制 STAB 就可能一击倒，而且 6 回合里有 3 回合出手系数是 1.0。
2. **半价券决定了一切。** 2 张券 = 6 个谷时回合，o1 在第一个窗口里就把 87 血打光，所以引导策略下 o1 只要 5 回合；不给券（0 张）引导 o1 要 14 回合，98%。券是教学的主角，但数值要让"没券"也有一条路，别让两张券把战斗缩成一个窗口。
3. **朴素在高峰回合白挨打。** 高峰 `takenMul` 0.15，高峰出手 ×1.0；朴素玩家 3 回合白挨一轮全伤害，所以朴素和引导的差距几乎全来自"高峰期怎么过"。要让"只打最高伤害"拿到 35–60%，Boss 要弱到引导玩家毫无压力，两个目标在这个机制里**不能同时成立**（扫了约 50 组 atk ×0.15–0.5、hp ×1–4、peak dealt 1.0–1.6，每组 3 个搭档）。
4. **V3 路线没有输出。** V3 的招式全是算力，打 V4（开源 + 推理）是 ×0.25；`addRules.family` 只把 V4 的伤害 ×0.6，没解决"V3 打不动"。即使把 atk 降到 0.25、hp ×3，V3 路线赢局也要 40+ 回合（V3 自己几乎不掉血、也几乎打不动）。

**改法（可落 JSON）：**

```json
"tiers": {"story": {
  "level": 12,
  "expMul": 2.0,
  "statMul": {"hp": 2.5, "atk": 0.3, "spa": 0.3},
  "byStarter": {"deepseek-v3": {"statMul": {"hp": 1.8}}},
  "rules": {"peak": {"dealtMul": 1.0, "takenMul": 0.15}, "valley": {"dealtMul": 0.5, "takenMul": 3.0}},
  "addRules": [{"id": "family", "if": {"foeCompany": ["DeepSeek"]}, "dealtMul": 0.6, "takenMul": [{"mul": 4.0, "note": "boss.deepseek.family"}]}],
  "residualMul": 0.4,
  "enrage": {"turn": 18, "warnBefore": 3},
  "assist": {"statMul": {"hp": 1.8, "atk": 0.2, "spa": 0.2}, "rules": {"peak": {"takenMul": 0.3}}}
}}
```

- 新字段：`BossTierDef.expMul`（见 I6）、`byStarter`（也可以走 §8.2 的 `starterBattle` 变体）。V3 的 assist 再把 hp 降到 1.3。
- **`family` 加 `takenMul ×4`** 抵消 ×0.25 的抵抗，剧情上就是"小 V3 的招式，姐姐舍不得躲"。我的模拟把认亲按全程近似（也让文心一言受益），所以 V3 路线的数字**偏乐观**，真正上线要用 `foeCompany` 条件重测 [unverified]。
- **目标要改定义：** "朴素"改成 pilot（不用道具的合格玩家），目标 35–60%；"纯打最高伤害"在 Lv8 队伍上拿不到分，本来就不该是目标。建议值下 pilot 是 o1 43% / Haiku 67% / V3 100%，引导 100 / 85 / 100。Haiku 引导 85% 低于 90%，要么 atk 再降到 0.25（pilot 升到 82%），要么接受并交给减负模式。
- **对等级很敏感：** 同一份数值，Haiku 引导在 Lv8/6/5 是 85%，在 Lv7/5/5 掉到 **34%**（上表之外的补充格，`/tmp/ap-review/final2.ts`）。所以 B1 的补经验不是可有可无，没补经验就要靠减负模式兜底。
- **陪练（`deepseek-drill`）也不是"输不了"：** 按 §8.2 原值（V2 Lv7、hp ×1.6、周期 4），朴素在 Lv8/6 上 Haiku、V3 都是 **0%**，o1 88%。改 `statMul` 为 `{hp: 0.8, atk: 0.3, spa: 0.3}`：o1、Haiku 100%（Lv6/4 与 Lv8/6），V3 在 Lv8/6 上 90%、Lv6/4 上 0%，V3 仍需要和上面同样的 `family`。

#### B3 Boss 卡：追赶前提不成立，上限和 §5.5 自相矛盾

**现象 1（追赶）：** §5.2 表（Lv10：3 场上场 / 7 场替补，Lv20：7 / 15，…）。

**证据：** 我用 0003 的公式（`min(10, 1+0.5×差距)`，替补 ×0.5，慢速曲线）复现了这张表，6 行完全一致 [verified]；但它的输入是"每个击杀都是与队伍同级的训练家，经验取 balance.md §7.1 的同级野生 ×1.25"。早期敌人不是同级，单个击杀经验只有同级的 1/5–2/3（路线一最低、馆内最高）：

| 签约后到二号路之前实际可得的击杀 | 经验（训练家 ×1.25，单个击杀） |
|---|---|
| 路线一余下：`r1-xiong` Lv5 / `r1-mei` Lv3+4 / `r1-zhou` Lv6 | 50 / 28+37 / 61 |
| 路线一野生 Lv3–6（可选） | 35 |
| 开源林镇馆内：`gc-xiaoma` Lv6 / `gc-ace` Lv7+7 / `gc-xiaoyuan` Lv8+8 / 馆主 Lv6+7+10 | 57 / 75+67 / 74+102 / 57+71+107 |
| 二号路 7 名训练家 Lv8–11 | 约 96 |

（`content/world/story/trainers/routes.json`、`gyms.json`；`r1-xin`、`r1-jie` 已在序章用掉。）

击杀序列 = 路线一 4 个 + 5 场野战 + 馆内 8 个 + 二号路 …，队伍最高等级取 10（二号路取 12）：

| 系数（perLevel / max） | 到队伍 Lv10：上场 / 替补 击杀数 | 到 Lv12：上场 / 替补 | 到开源林镇（4 个 + 5 野战）时卡的等级 上场 / 替补 |
|---|---|---|---|
| 0.5 / 10（0003） | **12 / 19** | 17 / 26 | **Lv9 / Lv7** |
| **1.0 / 12（建议）** | **9 / 14** | 13 / 19 | Lv10 / Lv8 |
| 1.5 / 12 | 6 / 12 | 11 / 17 | — |

0003 说的"3 / 7"差 3–4 倍（上场）和 2.7 倍（替补）；§3.4 的"到开源林镇约 Lv12"实际是 Lv9 / Lv7。**一场野战都不打**也行：0003 系数下上场的卡打完路线一余下 4 个 + 馆内 8 个到 Lv10，替补到 Lv9；建议系数下上场 Lv11、替补 Lv10。§8.8 M1 验收 6（"约 7 场替补 / 3 场上场到 Lv10"）会失败。

**现象 2（上限）：** `capByBadges` = 下一馆王牌 +2（§5.3），而 §5.5 约束 1 要求"卡在上限，个体取中值，单挑下一座馆主整队，胜率 ≤ 50%（首馆除外）"。

**证据：** 用 `BattleEngine` + 馆主真实队伍，卡 = V4（IV 19 约 A 级下限，带"权重空投"），单挑 100 个种子 [verified，`/tmp/ap-review/cardsolo2.ts`、`cardsolo3.ts`]。每格是 pilot｜朴素 的胜率：

| 卡等级 = 馆王牌 + d | 馆 2（王牌 17） | 馆 3（23） | 馆 5（33） | 馆 7（45） |
|---|---|---|---|---|
| +2（0003） | 100｜100 | 100｜100 | 100｜100 | 100｜0 |
| −2 | 100｜99 | 87｜88 | 100｜100 | 85｜18 |
| −3 | 95 | 52 | 92 | 47 |
| **−4** | 81｜33 | 1｜1 | **48**｜50 | **21**｜0 |
| −5 | 27 | 0 | 17 | 10 |

馆 4（检索）、6（对齐）、8（推理）在任何 d 下都 0%（属性克制拦住）。胜率在 3–4 级内从 0 跳到 100。0003 的上限（+2）在馆 2、3、5、7 单挑必胜，**等于"一张卡带飞一半的馆"**，§5.5 约束 1 无法满足。

**改法：**

1. 二选一，由所有者定（D3）：

### 重要

#### I1 性格取整：低等级时加成消失，减成保留

**现象：** §6.2 公式 `floor((floor((2B+IV)·L/100)+5)·N)`。

**证据 [verified]：** 种族值 60、IV 15：

| 等级 | 中性 | +10% floor（0003） | +10% ceil | −10% floor |
|---|---|---|---|---|
| 1 | 6 | 6（+0） | 7（+1） | 5（−1） |
| 5 | 11 | 12（+1） | 13（+2） | 9（−2） |
| 10 | 18 | 19（+1） | 20（+2） | 16（−2） |
| 30 | 45 | 49（+4） | 50（+5） | 40（−5） |

V4 卡 Lv1：攻击 7，×1.1 = 7.7 → 7（没变），×0.9 = 6.3 → 6（−1）。**Lv1–10 时随机性格的期望是负收益，签约出来 Lv1 的 Boss 卡看起来"性格箭头"全是惩罚。**

**改法：** `calcStats` 的性格项改成"加成向上取整、减成向下取整"（`ceil` / `floor`），保证 ±1 以上；`quality.json:natureMul` 不用动。同时 §6.2 的"低等级时影响小"改成"Lv10 约 ±2 点，Lv50 约 ±8 点"。

#### I2 品质阈值与 SS 稀有度

**现象：** 阈值 C<85、B 85、A 115、S 140、SS 165（§6.3）。

**证据：** 精确卷积复现 §4.2 的表，一致 [verified，`/tmp/ap-review/quality.py`]。补充：

| 来源 | C | B | A | S | SS |
|---|---|---|---|---|---|
| 野生 | 35.7 | 46.8 | 15.7 | 1.85 | **0.03%（约 1/3500）** |
| 剧情档 | 1.7 | 34.2 | 49.3 | 14.4 | 0.46 |
| 剧情档首签（拒绝采样 ≥115） | 0 | 0 | 76.8 | 22.5 | 0.71 |
| 进阶档 | 0 | 3.2 | 45.4 | 47.6 | 3.8 |
| 满血档 | 0 | 0 | 9.1 | 71.9 | **19.0%** |
| 满血档，阈值 S145 / SS170 | 0 | 0 | 19.0 | 71.9 | 9.1 |

- SS 在野生里 1/3500（几乎不可能），在满血档却是五分之一：**"天选"这个名字在满血档不稀有，在野外不存在**。
- 野生 S（≥140）1.85%：要抓同一物种 54 只，约 270–340 场战斗（按一个物种占遭遇 20%、N 级成功率 80%）≈ 3.5–5 小时，是长线目标，可以保留。

**改法：** `quality.json:grades` 改为 `{"id":"S","min":145}`、`{"id":"SS","min":170}`。满血档 SS 9.1%（约 11 次签约），进阶档 1.5%。其余阈值不动。

#### I3 签约概率与保底：显示值 ≠ 实际值；LoRA 让"凹"变成纯花钱

**证据 [verified，`quality.py`、`lora.py`]：** 保底后每次通关的实际签约概率：

| 档位 | 显示 | 每次通关实际（1 / 期望次数） | 期望次数 | 靠保底出的比例 |
|---|---|---|---|---|
| 剧情 35%，保底 3 | 35% | **42.6%** | 2.35 | 27.5% |
| 进阶 25%，保底 4 | 25% | **32.8%** | 3.05 | 31.6% |
| 满血 15%，保底 5 | 15% | **24.1%** | 4.15 | **44.4%** |

满血档近一半的签约是保底硬给的；显示"15%"会让玩家觉得被骗，显示"保底 x/5"已经在 §4.3 里写了，建议同时显示"平均约 4 次"。

"凹"的期望耗时（单次通关用时 剧情 3 / 进阶 4.5 / 满血 6 分钟 [assumed]）：

| 目标 | 剧情档 | 进阶档 | 满血档 |
|---|---|---|---|
| A 以上 | 4 次通关 | 3 | 4 |
| S 以上 | 16（约 48 分钟） | 6（约 27 分钟） | 5（约 30 分钟） |
| SS（现阈值 165） | 512 | 80（约 6 小时） | 22（约 2.2 小时） |
| SS（建议阈值 170） | — | 209（约 15.7 小时） | 46（约 4.6 小时） |

问题在 LoRA：补丁是 `新值 = max(旧值, random(0,31))`，每次选最低的一项，3 个残片（满血档 1 次通关）一次：

| 起点 | 到 S（≥140）平均补丁数 | 到 SS（≥165）平均补丁数 |
|---|---|---|
| 野生（均值 93） | 7.6 | 21.4 |
| 剧情档卡 | 3.9 | 14.0 |
| 进阶档卡 | 1.4 | 8.2 |
| 满血档卡 | 0.2 | **4.0**（p90 10） |

满血档卡 + 4 次补丁 = 4 次通关（24 分钟）就是 SS（≥165），连签约共约 8 次通关，比"硬刷到 SS"的 22 次快 2.7 倍；进阶档卡 8.2 次补丁（约 12 次通关）对 80 次。**补丁比重抽便宜，重刷的唯一理由变成攒残片，"凹"的随机性没有意义。**

**每只智灵限补丁次数不够**，我又算了限次后的分布（`/tmp/ap-review` 内联脚本，2 万次）：

| 补丁次数 | 野生 S+ / 平均加成 | 剧情档 S+ | 进阶档 S+ / SS170 | 满血档 S+ / SS170 |
|---|---|---|---|---|
| 0 | 1.1% | 9.0% | 37.6% / 1.4% | 80.7% / 9.4% |
| 2 | 8.0%（+21.5） | 31.6% | 68.4% / 7.9% | 94.2% / **28.5%** |
| 3 | 14.2%（+28.7） | 43.1% | 77.9% / 12.9% | 97.1% / **38.4%** |

（S+ 按建议阈值 ≥145，SS 按 ≥170。）3 次补丁把满血档的 SS 从 9.4% 抬到 38.4%，仍然稀释了稀有度。

**改法：**
- **LoRA 只能用在品质低于 S 的智灵上，且每只最多 3 次：** `items.json:lora-patch.effect` 加 `"maxGrade": "A"`、`"maxPerCreature": 3`，`Creature` 存 `finetuned: number`，详情页显示"微调 2/3"。结果：野生 C/B 卡 3 次补丁平均 +28.7，从均值 93 到约 122 = A，**LoRA 是"保底到 A"的省心路径**；满血档 81% 出生就是 S，补丁用不上，SS 仍然靠签约运气和蒸馏。
- 蒸馏不改：从满血档卡起，用 4.3 张满血档供体（每张约 4 次通关）才能全 31，是合理的毕业目标；不限次数，因为每个供体都是一张被消耗的卡。
- 性格重写卡和特性胶囊没有 SS 那种稀有度问题（`persona-card` 8 个残片 = 3 次满血通关，约 16 分钟），不改。

#### I7 经济闭环

- **蒸馏：** UR 供体 8000 Token 币 ≈ 满血档 1.1 次通关的钱，成本主要是供体本身（约 4 次通关一张），钱不是瓶颈；特性胶囊 5 残片 ≈ 1.7 次满血通关，也是时间成本为主。
