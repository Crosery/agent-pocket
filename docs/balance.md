# 数值框架与平衡 · Balance Framework

目标：数值有可复述的预算，能被工具复核，扩展时有规则可依；让"属性克制、队伍搭配、站位与节奏"比单纯的等级和稀有度更能决定胜负。

- 所有数值都在 `content/` 的 JSON 里（种族值由 `tools/data/build_species.py` + `species_rules.json` 生成）。代码里没有任何可调数值。
- 校验阈值在 `tools/balance/rules.json`，队伍原型在 `tools/balance/archetypes.json`，模拟策略权重在 `tools/balance/pilot.json`。
- `tests/balance-framework.test.ts` 把关键不变量接进 `npm test`；完整、更多场次的版本用 `node tools/balance/cli.ts <命令>` 运行（第 9 节）。

## 2. 种族值预算

### 2.1 稀有度带（BST = 六项种族值之和）

| 稀有度 | 带 | 现有数量 | 实际范围 | 均值 | 标准差 |
|---|---|---|---|---|---|
| N | 240–330 | 18 | 258–325 | 279.7 | 18.5 |
| R | 330–420 | 56 | 348–415 | 378.8 | 18.8 |
| SR | 420–490 | 88 | 434–490 | 465.8 | 16.9 |
| SSR | 490–550 | 63 | 502–550 | 532.6 | 13.3 |
| UR | 560–630 | 27 | 574–630 | 600.5 | 18.2 |
| MYTHIC | 640–720 | 3 | 656–715 | 678.7 | 26.0 |

规则：

1. 每只都落在自己稀有度的带内；带内偏离均值超过 2.6 个标准差算离群（`stats.outlierZ`）。
2. 稀有度之间的缝是设计出来的：相邻稀有度的均值差约 67–99，足以让高稀有度在同级对战中明显占优，但不是碾压（见第 6 节的稀有度阶梯）。
3. 单项种族值不低于 15、不高于 160，且不超过 BST 的 34%（避免"一条腿走路"的怪物）。
4. 生成器的 `bandFloor`（0.2）把带内偏弱的离群点抬到带下沿以上 20% 的位置，种族值总和不越界。

### 2.2 进化阶段

进化后的 BST 必须是进化前的 1.08–1.6 倍（生成器 `evolutionStep`，校验 `stats.evolutionBstRatio` 取更宽的 1.04–1.6）。116 条进化里 100 条升入更高的稀有度带，16 条留在同一带内；同一稀有度内一阶、二阶、三阶的 BST 均值没有固定梯度（进化形态大多已经升了稀有度），所以梯度完全由进化倍率约束。目前倍率最小 1.05、均值 1.23、最大 1.6。

### 2.3 定位（role）

`tools/balance/stats.ts` 用种族值形状给每只分类，用于检查"每个稀有度都有多种定位"和配队：

| 定位 | 形状 |
|---|---|
| sweeper 清场手 | 主攻 ≥ BST 的 21.5%，速度 ≥ 19% |
| wallbreaker 破盾手 | 主攻高，速度低，耐久不高 |
| tank 肉盾 | hp+双防+双特防 ≥ BST 的 56%，主攻低 |
| bulky-attacker 厚攻 | 主攻与耐久都高 |
| support 辅助 | 攻防都不突出，常靠速度或招式组合起作用 |
| balanced 均衡 | 其余 |

### 2.4 速度区间

速度只有大小关系有意义（谁先出手）。研究资料给出的速度跨度很大，会把"谁先手"变成稀有度之外的唯一变量，所以生成器的 `speedBand` 把速度向枢轴 80 压缩（保留 40% 的偏离），少给的点数按 hp/def/spd 退回（速度慢的物种反向让出），BST 严格不变。结果是：快不再等于无敌，慢速高耐久的物种能靠耐久换回价值。

## 3. 属性克制、本系加成与双属性

- 倍率只取 {0, ½, 1, 2}；本系加成（STAB）1.5；暴击 1.5；随机系数 0.85–1.0。
- 每个属性：克制 2–4 个，被克制 ≤ 4 个，抵抗 ≥ 2 个，不能没有弱点，也不能一个克制都没有（`rules.json` 的 `types`）。
- 全表至多 2 个无效；对话（普通位）以 1 个无效换来 3 个抵抗。
- 进攻指数与防守指数（对全部属性取倍率均值）必须在 0.95–1.2；两者之比不超过 1.5。
- 双属性：4 倍弱点的物种占全部物种 ≤ 25%（现为 255 只里 58 只，23%），双属性的抵抗与弱点叠乘，所以单属性表的区间收得比较紧。
- 属性克制的价值：同稀有度、BST 相差在 25 以内时，持有克制 STAB 招式的一方，对手高 6 级（SR 一档）胜率仍有约一半；换算下来一次克制约等于 6 级的差距，比稀有度的一个台阶（SR 比 R 低 5 级时胜率 45%）更有分量。

本次改动：`sound -> vision` 由 0 改为 ½。调整前声音的进攻指数 0.96，贴着 0.95 的下限，视觉还对声音完全免疫；调整后声音 1.0，全表的无效招数少一个。

## 4. 招式价值

价值 = 威力 × 命中 × 连击数，再按下表加减，PP 必须落在对应价值的窗口里。

### 4.1 威力、PP 窗口

| 价值（≈威力）上限 | PP 窗口 |
|---|---|
| 30 | 25–40 |
| 50 | 20–40 |
| 70 | 15–30 |
| 90 | 10–25 |
| 115 | 5–20 |
| 其上 | 5–15 |

- 威力上限 160（自爆类 220，按价值 ×0.5 折算）；无威力的固定伤害招式（`fixedDamage`）单独核算。
- 优先级招式价值 ×1.1；后坐力 ×0.7；需要蓄力 ×0.55；自爆 ×0.5。

### 4.2 状态与效果的价值

| 效果 | 价值 |
|---|---|
| 睡眠 / 冰冻 | 55 |
| 宕机（麻痹） | 40 |
| 灼烧 / 中毒 / 其他状态 | 30 |
| 混乱 | 28 |
| 回复 | 40 |
| 吸取 | 威力 ×0.3 |
| 天气 | 30 |
| 攻 / 特攻 / 速度提升（每档） | 14 |
| 防 / 特防提升（每档） | 10 |
| 畏缩 | 10 |
| 高暴击 | 6 |

状态招式按类型各有 PP 窗口：回复 5–15、天气 5–10、保护 5–15、强化 15–30、异常 10–30、削弱 15–30。

### 4.3 命中

没有伤害、只靠 100% 概率附带异常的招式，命中率没有任何价值补偿，低命中只会让控场队被运气否决。本次把这类招式中命中低于 100 的统一提高了 15（上限 100，见第 11 节）。

## 5. 战斗节奏

伤害公式见 `docs/battle-rules.md`：

`伤害 = floor(floor(floor(2L/5+2)·P·A/D) / divisor) + add`，再乘随机、克制、本系、暴击等系数。

`divisor` 在 `content/battle_rules.json`，本次由 50 调到 80。原因：评测里"同级、同稀有度、用最佳本系招式"打中立目标，中位 2.1–2.2 下 KO，克制几乎一击；这样"谁先手、谁属性对"之外几乎没有策略空间，辅助、强化、回复也没有时间发挥。

目标带（hits-to-KO 中位，`rules.json` 的 `ttk`）：

| 对位 | 目标 | 调整前 | 调整后（Lv 10 / 30 / 50 / 70） |
|---|---|---|---|
| 中立 | 2.4–4.6 | 1.9–2.2 | 2.9 / 3.3 / 3.4 / 3.4 |
| 克制 | 1.3–2.8 | 0.9–1.0 | 1.4 / 1.6 / 1.6 / 1.7 |
| 被抵抗 | 4.5–14 | 4.0–4.6 | 6.4 / 7.1 / 7.1 / 7.2 |

特性倍率同步收紧，避免叠加后出现 3 倍以上的伤害：混合专家 ×1.3 → ×1.2；多模态本系加成 2 → 1.75；超频 ×1.3 → ×1.2；狙击暴击倍率 2.25 → 2；共振 ×1.3 → ×1.2。睡眠回合 1–3 → 2–4（原先常常第一回合就醒来）。

## 6. 队伍原型与搭配

七个原型是从真实物种按角色规则自动组队的（`tools/balance/archetypes.json`），每个原型 24 个不同队伍，每队六只。

| 原型 | 打法 |
|---|---|
| hyper-offense 速攻队 | 高速度输出手一路强攻，在对手展开前连续击倒 |
| wall-stall 耐久队 | 高双防 + 回复，用数据污染和过热耗死对手，被克制时换抗性队友 |
| setup-sweep 强化流 | 趁对手出手不重时叠到 +2，再横扫 |
| status-control 控场队 | 限流、宕机、幻觉轮番上，夺走回合再收割 |
| weather-rush 超频队 | 先开算力过载，算力 / 代码属性招式 ×1.5，同时压制对面的对齐系 |
| balanced 均衡队 | 可靠的本系输出 + 覆盖 + 一点回复 |
| glass-cannon 重炮队 | 极高攻击的脆皮，拼谁先开火 |

组队律（`law`，保证比较公平）：

- 每队 6 只，队伍 BST 在 3150–3230，稀有度只取 SR–SSR。
- 同属性至多 2 只（超频队 4 只，因为它靠属性起作用），至少覆盖 8 种属性。
- 招式按槽位挑（输出、先制、回复、保护、强化、异常、混乱、天气、削弱、解除），输出招式要有覆盖面（`attackFloor` 0.6）。
- 每个物种用随机个体值（0–31），首发顺序随机，天气手固定首发。

对战策略（`pilot`）：按期望伤害选招，评估异常 / 强化 / 回复 / 天气的收益，在被克制或血线危险时换人。游戏内 AI 也可以用（`--game-ai`），但它不会强化、天气与异常配合，所以只作兜底参照。

判定（`rules.json` 的 `sim`）：

1. 没有任何原型对所有其他原型胜率都 > 65%（不存在"通吃"）。
2. 每个原型都至少有一个 ≥ 55% 的克制对象，也至少有一个 ≤ 50% 的对手。
3. 全场平均胜率在 33%–68%。
4. 存在克制环（A 克制 B，B 克制 C，……，回到 A）。
5. 平局率 ≤ 8%。

## 8. 扩展规则

**新增物种**：在 `tools/data/` 的名册里加，跑 `python3 tools/data/build_species.py`，再跑 `python3 tools/content_fmt.py`；生成器会把 BST 放进稀有度带、套用进化倍率与速度压缩。然后跑 `node tools/balance/cli.ts stats`，输出"outliers: 0"。

**新增属性**：必须同时给出克制与被克制关系，满足第 3 节全部区间；`python3 tools/data/typechart_md.py` 重新生成文档；跑 `node tools/balance/cli.ts types`。新属性要有足够的 SR 以上物种，否则 `solo` 的属性强度表样本太少（检索只有 7 只就已经偏离）。

**新增招式**：从第 4 节的价值表定威力与 PP；`node tools/balance/cli.ts moves` 报告越界与同 PP 的价值离群。

**新增地区 / 道馆**：道馆等级与强度比遵守第 7.2 节；遇敌等级范围要和 `content/world/regions.json` 的 `levelRange` 对应；奖金随馆序递增。跑 `node tools/balance/cli.ts curve`。

**新增队伍原型**：在 `tools/balance/archetypes.json` 增加一个角色（`score` 排序、`where` 的最小门槛、招式槽位），跑 `node tools/balance/cli.ts teams` 看代表队，再跑 `matrix` 看是否满足第 6 节的判定。

**调阈值**：改 `tools/balance/rules.json` 须在提交信息写明理由；不要为了让某个新数据通过而放宽阈值。

## 9. 工具与复现

```
node tools/balance/cli.ts types      # 属性覆盖、弱点与进攻 / 防守指数
node tools/balance/cli.ts stats      # BST 分布、进化倍率、离群
node tools/balance/cli.ts moves      # 招式价值与 PP、离群
node tools/balance/cli.ts ttk        # 击杀回合带
node tools/balance/cli.ts curve      # 经验、道馆、经济
node tools/balance/cli.ts teams      # 每个原型的代表队
node tools/balance/cli.ts matrix [--n 400] [--seed 1] [--level 50] [--game-ai]
node tools/balance/cli.ts solo   [--per 10] [--games 6]   # 稀有度阶梯、属性强度、克制边的等级当量
node tools/balance/cli.ts all        # 除 matrix / solo 外全部
OPENING_REPORT=1 node --test tests/opening_balance.test.ts   # 新手期胜率表
```

`matrix` 默认每组 400 场（24 个队伍实例轮换，种子 1）。胜率估计的标准误约 ±2.5 个百分点，所以接近阈值的单元格要看多个种子。

读法：速攻队对其余五队都 ≥ 61%，只有超频队能与它打平（48% / 52%）；超频队压制强化 / 控场 / 均衡 / 重炮，却被耐久队反压（29%）；耐久队的唯一猎物是超频队（71%）；控场队（58%）与强化流（56%）反制耐久队，控场队又输给超频队（41%）。最短的克制环是耐久 -> 超频 -> 控场 -> 耐久。用三个种子（1、2、3）、每组 400 场复测，场均胜率稳定在速攻 63–65%、耐久 46–48%、强化 40%、控场 52–54%、超频 63–65%、均衡 42–43%、重炮 38–40%，判定三次都是 OK。

## 12. 已知局限

- 原型矩阵依赖 pilot 策略与自动组出的队伍；游戏内 AI 不会强化、布天气、配合异常，用它跑矩阵不再有闭环（`--game-ai`：速攻 60%、超频 62%、耐久 56%、强化 40%，没有克制环）。数值服务的是会玩的玩家，AI 的能力是另一个议题。
- 超频队的强势主要来自属性搭配，天气本身生效的回合比例约 10%；若要让天气成为真正的取舍，需要再调天气招式的威力或持续回合，这会影响全部天气队。
- 属性强度跨度 37%–61%（对话 / 声音 / 代码偏弱，视觉 / 检索偏强）来自物种池，不是克制表。要继续收窄，应在名册层面给弱属性加物种，而不是改倍率。
- 速攻队 65%、超频队 63–65% 仍是场均最高的两档，没有越界（规则上限 68%），但如果后续增加更强的先制或天气手，应优先在这两档上复测。
- 除数调大后六对六平均 22 个回合，比之前长约 70%；战斗动画与"跳过"选项的节奏需要在界面侧另行评估。
- 首馆馆主对朴素策略的胜率余量只有 11 个百分点（claude-haiku 81% 对阈值 70%），该测试是有种子的，所以结果稳定，但新增或调整御三家时要复测。
