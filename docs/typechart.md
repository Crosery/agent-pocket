# 属性克制表 · Type Chart

数据源：`content/types.json`（`chart` / `statusImmunities`）。本文件下方的矩阵与汇总表由
`python3 tools/data/typechart_md.py` 从 JSON 生成，改了克制关系后重跑即可；`--check` 用于检查文档是否过期。
`tests/data.test.ts` 校验倍率只取 {0, ½, 1, 2}、每个属性 2–4 个克制、1–4 个抵抗、全表至多 2 个无效（现为 1 个）。

## 设计原则

- **13 属性 × 2–3 个克制 / 2–3 个弱点**：没有"万金油"，也没有纯靶子；对话（普通位）以 1 个无效换来 3 个抵抗。
- **克制大多可逆**：A 克制 B 时，B 打 A 通常是 ½，让"属性相克"在攻防两端都成立。
- **四个闭环**支撑整张表：
  - 信息环：推理 → 幻觉 → 检索 → 推理（推理识破幻觉、幻觉污染检索、事实推翻空想）。
  - 硬件环：算力 → 代码 → 推理 → 算力（规模碾压代码、代码执行胜过心算、巧思以小博大）。
  - 媒体环：创作 → 影像 → 视觉 → 创作（剧本驱动影像、动态胜过静态、一图胜千言）。
  - 治理环：对齐 → 开源 → 代码 → 对齐（合规约束开源、众人审码、漏洞绕过护栏）。
- **无效只有 1 处**（对话 → 算力），来自"感知通道不匹配"这种一眼能懂的设定；音律 → 视觉原为无效，改为 ½（视觉模型听不见声音，但配乐与字幕仍能影响它），让视觉不再兼具"唯一免疫"与"低弱点"，攻防指数回到均值附近。

## 游戏内的克制表

菜单 →「属性克制表」（或教学手册的属性克制页、研究所阿灵的课、战斗里「效果拔群 / 效果不佳」提示卡的按钮）打开 `typeChart` 界面，三个视图读的都是 `content/types.json`，界面里没有写死任何属性：

- **单个属性**：选一个属性，分「进攻」（克制 ×2 / 效果不佳 ×0.5 / 无效 ×0）和「防守」（弱点 ×2 / 抵抗 ×0.5 / 免疫 ×0）两栏，各列出对应属性，并附一句例子。哪些倍率各占一行、行的颜色在 `content/screens.json` 的 `typeChart.matchups`。
- **完整表格**：13×13，行是出招方、列是挨打方，×2 / ×½ / ×0 着色标记，×1 留空；光标所在的行列高亮，旁边说明这一对的结果和理由（`screens.typeChart.reason.<攻>.<防>`），附图例。手机上格子保持 44px 可点，表格可拖动，表头跟着滚。
- **克制闭环**：「初始三角 / 硬件环」「信息环」「媒体环」「治理环」画成箭头环（`content/tutorial.json` 的 `typeChart.loops`）。初始三角（推理→算力→代码）就是硬件环绕一圈，所以只画一份。

`tests/typechart.test.ts` 断言每个闭环的每条边在 `chart` 里确实是 ×2，`validateTutorial` 也会检查，改克制表时教学不会和数据对不上。

## 抵抗与无效

- 抵抗（½）多为克制的反向：被克制的一方打回去效果不好（例：幻觉打推理、检索打对话、代码打开源）。
- 自抗：代码、创作、影像、音律抵抗同属性（重复的套路彼此免疫）。
- **对话 → 算力 = 0**：算力集群只是硬件，不会陪你闲聊。

## 异常状态免疫

| 状态 | 免疫属性 | 设定 |
|---|---|---|
| 过热 `burn` | 算力 | 自带液冷散热系统。 |
| 数据污染 `poison` | 对齐 | 数据清洗与过滤管线。 |
| 限流 `sleep` | 开源 | 本地部署，不受 API 限流。 |
| 死锁 `freeze` | 代码 | 内置死锁检测与超时重试。 |
